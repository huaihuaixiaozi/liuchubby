# Release / dsh-market inclusion metadata

Copy-paste values for publishing this repo so it is discoverable and
installable as a bundle plugin.

> **Layout: the package lives in `agent-skills-dsh/`, not at the repository
> root.** Every install spec and market entry URL below therefore carries the
> subdirectory. The market's CI reads `package.json` from the **default branch**
> at the path the entry URL names, and it ignores the branch segment — only
> `main` is ever read.

## dsh-market listing (awesome-dsh-plugin PR)

The market (`dsh-market/dsh-market`) reads the curated list
`awesome-dsh-plugin/awesome-dsh-plugin`. To list this plugin, open a PR there
adding **one file**,
`data/plugins/huaihuaixiaozi__liuchubby--agent-skills-dsh.yml`:

```yaml
url: https://github.com/huaihuaixiaozi/liuchubby/tree/main/agent-skills-dsh
name: huaihuaixiaozi/liuchubby#agent-skills-dsh
category: skill
description:
  en: 24 engineering workflow skills, 4 review personas, and 8 lifecycle slash commands for DeepSeek Harness.
  zh: DeepSeek Harness 的 24 个工程工作流技能、4 个评审 persona 与 8 条生命周期斜杠命令。
```

The filename must equal the URL's slug: a subdirectory entry is
`<owner>__<repo>--<subdir>`, not `<owner>__<repo>`. CI rejects a mismatch, and
it rejects a root-pointing URL outright when the root has no `dsh.bundle`:

```
url: https://github.com/huaihuaixiaozi/liuchubby
name: huaihuaixiaozi/liuchubby
```

## Install notes

- **The package lives in `agent-skills-dsh/`.** A root-pointing spec installs
  nothing, because the repository root holds no `package.json`.
- **Git install needs no build authorization.** This package is plain ESM
  (`index.mjs` + `skills/`), no TypeScript build and no `prepare` script, so
  `dsh plugin --profile web add github:huaihuaixiaozi/liuchubby#path:/agent-skills-dsh`
  works without a pnpm `allowBuilds` entry.
- For a local/dev install: `dsh plugin --profile web add ./agent-skills-dsh`.
